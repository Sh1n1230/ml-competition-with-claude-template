# 統計・MLガイドライン

詳細は `.claude/skills/statistical-ml-review/SKILL.md`。ここではコンペ固有の要点。

## 必ず先に決めること

- 目的変数と分析単位（1行が何を表すか）
- fold 方式（`competition-workflow` の表）と seed
- 評価指標のローカル実装（公式と一致すること）
- 提出形式（ラベルか確率か）

## リーケージ

- fold をまたぐ集約特徴量・target encoding を作らない
- 同一エンティティを train/valid に跨がせない
- 未来情報を使わない（時系列）
- 「CV が急に跳ねた」ときは、まずリークを疑う

## 検証の規律

- 後付け最適化（blend重み・閾値・pool構成）は **nested-CV** で採否を決める
- CV と LB が食い違うときは **n の大きい方**を信じる
- 単一 seed の差は誤差。重要な判断は複数 seed の平均で
- ハイパラ探索は最後。効果が最も小さい

## 報告

モデルの結果を報告するときは、CV・fold ごとのばらつき・使用特徴量・
baseline との差分を必ず添える。「良くなった」だけの報告はしない。
