# Security policy

## Reporting a vulnerability

Please do not open a public issue for a security vulnerability. Use
[GitHub private vulnerability reporting](../../security/advisories/new)
when available. Include the affected file or workflow, reproduction steps, and impact.

If private reporting is unavailable, contact the repository owner through their GitHub
profile and avoid sharing credentials or competition data.

## Data and credentials

Never commit competition datasets, external datasets, API keys, tokens, private keys,
or personal information. The repository includes checks for common accidental leaks,
but contributors remain responsible for reviewing their changes.
